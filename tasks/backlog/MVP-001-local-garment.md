# MVP-001：添加一件衣物并在重启后重新看到

## 用户价值

用户无需账号即可从相册或相机添加一件真实衣物，确认基本信息，在衣橱中打开、编辑和保留。

## 场景与流程

衣橱空态 → 添加衣物 → 选择/拍摄照片 → 确认名称、类别、颜色、季节和场景 → 保存 → 衣橱网格 → 单品详情 → 重启后仍存在。

对应规格：IMP-01、IMP-05、CLS-01、CLS-03、CLS-04。

## 必须完成

- 建立版本化 SQLite/Drizzle schema、迁移、DAO 与 App 私有图片目录。
- 原图复制进 `originals/`，计算哈希与尺寸；数据库只保存路径和元数据。
- 支持权限拒绝、选择取消、文件不可读、重复导入和磁盘写入失败。
- 保存操作具有事务边界；数据库失败时不得留下无主派生文件。
- 衣橱空态、网格、详情和编辑使用真实持久化数据。
- 图片权限在用户点击添加后再申请；不用定位和账号。

## 不做

- 不做自动抠图、推荐、批量导入、搜索筛选或云同步。
- 不把图片转成 Base64 存进状态或数据库。

## 状态与失败恢复

- 保存失败保留用户已填内容并允许重试。
- 原图缺失时显示可修复状态，不删除衣物记录。
- 重复图片提示但允许用户明确继续添加。

## 验收标准

- 新安装无账号添加一件衣物，杀进程重启后网格和详情数据一致。
- 编辑名称/标签后重启仍存在；删除采用可恢复墓碑。
- 原相册文件被删除后，App 私有副本仍可打开。
- 点击目标和字体缩放满足 `AGENTS.md`。

## 测试与证据

- DAO 迁移、事务回滚、重复哈希、缺失文件和进程重启有自动测试。
- Maestro/真机流程覆盖拒绝权限后恢复与一次完整保存。
- 反向验证：临时让目标目录不可写或注入写入失败，证明 UI 显示失败且数据库无半条记录；还原后通过。
- 保存 CLS-01、CLS-03、IMP-01、IMP-05 真机截图。
