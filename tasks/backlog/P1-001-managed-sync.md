# P1-001：用户主动开启的多设备同步与冲突解决

## 用户价值

需要跨设备的用户可主动登录并同步，同时本地单机用户不被迫注册或上传私人照片。

## 场景与流程

SET-02 查看将同步的数据和加密说明 → 登录/开启 → SET-03 查看状态与失败 → 多设备编辑 → SET-04 解决冲突 → SET-08 删除云副本但可保留本地。

## 必须完成

- 使用 Supabase Postgres + PowerSync 的本地 SQLite 同步模式；图片对象与元数据分离。
- 开启前明确数据量、网络、供应商、保存期限和删除路径。
- 操作日志可重放，删除用墓碑；造型画布冲突可并排选择或合并。
- 用户级行权限、短时签名 URL、设备撤销和云删除有服务端测试。
- 同步关闭后本地核心功能继续工作。

## 不做

- 不默认开启，不把免费云配额当生产 SLA。
- 不同步 SecureStore 密钥、日志全文或未授权原图。

## 状态与失败恢复

- 离线、令牌过期、部分图片失败、服务暂停和冲突都有可见状态。
- 云删除失败不能谎报成功；本地删除与云删除分别确认。

## 验收标准

- 两台设备离线编辑后能同步或进入明确冲突，不静默覆盖。
- 越权读取和对象路径猜测均失败。
- 删除云副本后服务端验证不存在，本地按用户选择保留或删除。

## 测试与证据

- 集成测试覆盖 RLS、离线重放、冲突、令牌过期、部分失败和删除。
- 反向验证：用第二用户读取第一用户记录和对象，证明拒绝。
- 保存 SET-02、SET-03、SET-04、SET-08 实现截图。

## 依赖与优先级

优先级 P1，依赖 MVP-014；需要用户明确授权创建测试云资源后才能开始。
