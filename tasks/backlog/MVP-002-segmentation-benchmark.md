# MVP-002：证明选定分割 API 在真实衣物上可用

## 用户价值

在投入完整交互前，确认用户真实拍摄的衣物经现成分割 API 能得到足够好的透明蒙版，且免费额度覆盖日常用量（首次 12 件 + 日常零星新增）。

## 场景与流程

准备照片集 → 用统一适配层跑默认引擎腾讯云数据万象 GoodsMatting（2026-07-31 用户选定）→ 记录质量、端到端耗时、失败和额度消耗 → 在 Android 真机复测 → 确认默认达标并记录备用候选。

## 必须完成

- 复用可复跑的本地基准脚本、数据清单格式和不入库的私有样本目录（现有 host tsx+pngjs 管线）。
- 样本目标 100–200 张，覆盖白/黑衣物、毛发/蕾丝/流苏、鞋包、衣架、阴影和复杂背景；真实自拍不足时用公开衣物数据集（如 DeepFashion 子集）补足并在清单标注来源。
- 输出逐图结果、联系表、人工判定字段和汇总报告；不得只挑最好看的例子。
- 实现 `RemoteSegmentationEngine` 适配器：multipart 文件上传、返回含 alpha 蒙版的 PNG、key 从 expo-secure-store 读取、不经 JS 层整图 Base64 中转。默认实现腾讯云 GoodsMatting：上传时处理（PUT + Pic-Operations）→ 下载结果 PNG → 用完即删 COS 对象，照片不在云端留存。
- 验证默认引擎达标，写明免费额度数字、数据保留条款和大陆可达性结论；备用候选（阿里云 SegmentCloth、百度智能抠图）只记录结论，不实跑。

## 不做

- 不构建完整导入 UI；不做端侧推理（已移出 P0，见 `TECH_STACK.md` 第 4 节）。
- 不凭官网样张宣称可用；不用付费额度刷高样本量。

## 状态与失败恢复

- 若样本不足，使用公开可复现样本完成管线，但卡片保持 `BLOCKED`，不得标记最终验收。
- API 返回异常格式、超时、额度耗尽必须保留原始响应，淘汰该候选而不是隐藏样本。

## 验收标准

- 样本直接可用率 ≥80%，严重失败率 ≤5%。
- 单张端到端（含上传）目标 ≤8 秒、硬上限 15 秒；连续 12 张无重复扣费、无静默失败。
- 每个候选都有同一批样本结果和同一判定规则。
- 报告明确默认、备用、淘汰原因、免费额度与数据保留条款摘要、仍需手修的边缘类型。

## 测试与证据

- 自动校验样本数、结果数、缺失输出、透明通道、耗时与报告一致。
- 保存设备型号、系统、API 端点、响应哈希、p50/p95 端到端延迟。
- 反向验证：故意放入损坏图片或错误 key，证明基准非零退出且报告标红；恢复后全绿。

## 依赖与优先级

优先级 P0，依赖 MVP-001。它是 MVP-003 的硬门槛。
