# DEMO-001：可录屏的完整产品体验

## 简介

把现有 Android 智能衣橱收口成可安装、可重复演示、5–7 分钟能讲清核心卖点的 Demo。核心链路必须真实可交互和持久化；非核心信息允许使用确定性内置数据，但不得伪装成云端实时能力。

## 我替领导拍的板

- 导航保留四主标签：今日、衣橱、造型、计划；洞察从衣橱进入，设置从齿轮进入，购物守门为次级入口。
- 完全移除天气及备份/导出/恢复；不做账号、云同步、Pro、iOS 和商店上架。
- 推荐设置提供：场合、颜色协调、久未穿、避免近期重复、反馈偏好、主角单品。库存可用性与槽位合法性属于安全硬约束，不允许关闭。
- 演示包固定 54 件带透明底实图的衣物、18 套造型、20 天穿着历史、7 条计划、洞察图表和一个购物案例；重置结果必须一致。
- 旅行代码可以保留，但不进入主录屏线；未完整页面不暴露主入口。

## 界限

允许修改 `apps/**`、`packages/**`、`scripts/**`、任务和进度文档、根工程依赖配置。保留用户现有数据和无关改动；不推送远端、不建云资源、不删用户真实衣物。不得用静态截图替代页面、用假成功代替核心持久化，或为通过门禁删除/跳过无关测试。

## 现状与任务 0：固定基线

先运行并记录：

```powershell
git rev-parse --show-toplevel
git status --short
pnpm typecheck
pnpm test
pnpm lint
```

已知基线：Release APK 可构建；当前 typecheck/test/lint 被未完成 backup 测试和两个设置页 lint 错误阻断；当前无可用 Android 设备，AVD 缺 system image。实际输出写入 `PROGRESS.md`，不得把构建成功等同运行成功。

## 任务 1：删减产品面

移除今日页天气条、天气面板、定位/天气权限与网络调用；删除无调用的天气模块和依赖，但历史 schema/migration 若删除会破坏老数据则只保留兼容读取。移除 backup/export/restore 测试、服务、设置项、路由、文案及专用依赖。验收：全仓搜索无用户可见天气/备份入口；老数据可启动；全量门禁不再因 backup 失败。

## 任务 2：推荐参考要素设置

新增真实可达的设置入口与多选页面；选择跨重启保存。生成/换一套/只换一件都读取同一配置；关闭某要素后对应加分和理由不得出现，开启后用固定夹具可观察地改变结果。硬约束始终生效。先写配置解析、持久化和推荐影响的 RED 测试，再实现 GREEN。

## 任务 3：确定性 DemoDataPack

提供“载入/重置演示数据”，固定写入 54 件合法衣物及其内置图片、18 套造型、20 天穿着记录、7 条日历计划和购物候选；重复执行幂等，失败原子回滚，不触碰用户真实数据。图片随 APK 离线分发，首次载入复制到 App 私有 originals 目录，已存在原图不得覆盖。洞察必须从演示穿着事实实时计算，不硬编码 KPI。

## 任务 4：录屏主线与页面打磨

打通：载入演示衣橱 → 今日推荐与理由 → 设置切换要素 → 重新生成 → 只换一件 → 记录已穿 → 日历安排 → 洞察变化 → 购物报告。修复主线上所有死点击、加载抖动、遮挡、错误空态；覆盖 390×844、360×800、430×932 和 1.3×字体。统一纸白、炭黑、酒红、哑金视觉和 48×48 优先命中区。

## 任务 5：验证与交付

运行 `pnpm typecheck`、`pnpm test`、`pnpm lint`、`git diff --check` 与 Release 构建。关键约束做一次可恢复 RED→GREEN 反向验证。设备可用后安装 APK，按 5–7 分钟脚本冷启动录屏，并验证记录/设置/计划在 force-stop 后仍存在；无设备则写入 `BLOCKED.md` 并明确仅完成 host/构建证据。

## 规矩

只允许本卡 `IN_PROGRESS`。每个可验证小步立即更新 `PROGRESS.md`；同一验收连续失败三次保留原始输出并换方案。不得 `.skip/.todo`、删无关测试、放宽断言、伪造截图或用永远成功的命令。任何迁移、重置和清理先证明不伤用户数据。

## 完成条件

- 主录屏线无死点击、无崩溃、无天气/备份/导出入口。
- 推荐要素选择真实影响结果与理由，且跨重启保留。
- 计划/日历、记录已穿、洞察联动真实持久；演示重置确定且幂等。
- 全量门禁、Release APK、三尺寸与 1.3×字体通过。
- Android 冷启动、force-stop 持久与完整录屏有实际证据；外部阻塞如实列出。
