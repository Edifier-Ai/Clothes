# MVP-003：批量抠图、审核和手工修边可恢复

## 用户价值

用户一次选择多张衣物照片，能看到真实进度，失败可重试，边缘不好可手工修正，App 中断后不会从头再来。

## 场景与流程

IMP-01 批量选择 → IMP-02 持久队列 → IMP-03 原图/抠图审核 → IMP-04 擦除/恢复 → 保存蒙版 → 继续下一张。

## 必须完成

- SQLite 持久队列包含 `pending/running/succeeded/failed/cancelled`、尝试次数和错误码。
- 前台顺序推理默认并发 1；每张完成即提交。异常 `running` 在重启后安全回到可重试状态。
- 断网或 API 不可达时任务保持 `pending`，联网后自动续跑；用户可随时跳过，不阻塞衣物入库。
- 保存原图、alpha 蒙版、透明预览和缩略图；派生图可重建。
- 审核支持原图/透明/对比底色；修边支持缩放、平移、画笔大小、擦除、恢复、撤销和重做。
- 失败可以重试或跳过，不阻塞衣物入库；退出时明确剩余数量。

## 不做

- 不承诺系统后台按时执行；除分割 API 上传外不引入其他云服务。
- 不做人物换装、生成式补图或全自动无审核。

## 状态与失败恢复

- 杀进程、低内存、API 失败/超时/额度耗尽、单图损坏、空间不足都有明确恢复。
- 修边保存失败保留操作栈；原图绝不被覆盖。

## 验收标准

- 连续导入 12 张，进度、成功、失败和重试数量准确；杀进程重启后从已提交位置继续。
- 手修一张后退出重进，蒙版、撤销边界和透明预览一致。
- API 失败或断网时仍能保存未抠图衣物，并在详情中再次处理。

## 测试与证据

- 队列状态机、幂等恢复、文件原子写入、操作栈和派生图重建有测试。
- 记录 12 张任务的处理时间、峰值内存、失败注入和恢复结果。
- 反向验证：处理第 6 张时强制终止进程，证明前 5 张不重做且剩余任务恢复。
- 保存 IMP-02、IMP-03、IMP-04 真机截图及一段修边录屏。

## 依赖与优先级

优先级 P0，依赖 MVP-002。
