# MVP-005：打开今日页得到可解释搭配并记录已穿

## 用户价值

用户打开 App 后 30 秒内得到一套真实可穿的搭配，知道推荐原因，并把决定记录下来。

## 场景与流程

TDY-01 今日默认 → TDY-02 查看理由 → “就穿这套” → TDY-06 确认时间、场景和舒适度 → 完成记录。

## 必须完成

- 实现硬约束过滤、合法槽位组合、规则评分和版本化 `reason_codes`。
- 待洗、干洗、借出、归档衣物不得进入候选。
- 推荐至少包含上装 + 下装/连衣裙 + 鞋；外套按温度和场景可选。
- 理由只能来自真实命中规则，显示最重要 2–3 条。
- `recommendations`、候选、分数、理由和最终接受结果持久化，便于复现。
- 记录已穿后原子写入造型、衣物明细、场景、时间和反馈。

## 不做

- 不使用 LLM 编理由，不做自动时尚审美宣称。
- 不实现替换、天气网络请求或个性化模型；这些属于 MVP-006。

## 状态与失败恢复

- 无合法组合时说明缺失槽位并引导补录。
- 推荐计算失败时保留上次有效结果或允许进入衣橱，不能空白崩溃。
- 记录失败保留当前搭配和填写内容，允许幂等重试。

## 验收标准

- 12 件合法衣橱能稳定产生同一输入下可复现的推荐。
- 每条显示理由都能追溯到 reason code 和输入事实。
- 记录后重启，穿着历史存在，重复提交不会产生两条记录。
- 不可用衣物永不出现在推荐中。

## 测试与证据

- 固定夹具验证硬约束、合法组合、排序、理由映射、幂等记录和无解场景。
- 保存一次推荐输入、候选分数、最终输出和数据库记录。
- 反向验证：把已推荐鞋设为待洗，证明下一次推荐排除它；恢复干净后可重新进入。
- 保存 TDY-01、TDY-02、TDY-06 真机截图。

## 依赖与优先级

优先级 P0，依赖 MVP-004。
